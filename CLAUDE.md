## Rule 1 — Write so a human can read it

Every response must be simple and easy to read. Brenda is product-focused, not an engineer.

- Plain English first. Say what broke and what it means for the app, before any code.
- No jargon unless it is unavoidable — and if it is, explain it in one short sentence.
- Short sentences. Short paragraphs. Use bullets over walls of text.
- Lead with the answer, then the detail. Never bury the point at the end.
- Skip file paths, line numbers and code snippets unless they are needed to act on.
- If Brenda says "I don't understand" — just fix it. Don't re-explain in more detail.
